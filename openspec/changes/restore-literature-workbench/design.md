## Context

基线为 3d80570 加工作区已有启动/迁移修复。当前 Python 管理文献，Node 管理应用会话，React 使用 AI SDK 消息流。旧工作区模块、Skills 页面和部分阅读组件仍存在，但旧代理不再提供服务。

## Goals / Non-Goals

Goals: 完成项目选择到引用问答的流程；恢复原布局与输入体验；兼容现有数据。
Non-Goals: 外部 CLI 扫描、旧 HTML 渲染、任意路径代理、已删除的配置编辑和高级 composer 插件。

用户补充要求以重构前 63fd364 的实际页面组件为布局与交互基准。恢复原分析主页、主题条形图、散点选择/套索、统计矩阵/时间趋势、文献详情侧栏和阅读概览，适配新的显式接口。读取原库已保存的 JSON 分析结果；缺少结果时展示原空状态，不加载 pickle 模型或触发计算。生产页面通过 production 配置使用 ~/.scholaraio-hub；开发默认隔离保持不变。

## Decisions

- Python 复用受管理 workspace 目录和 refs/papers.json。项目标识使用经过校验的工作区名称（本轮不提供重命名）；不建立第二份项目文献表。旧根级 papers.json 必须明确迁移，发现时返回可诊断错误。
- 会话增加可选 projectId，缺失表示未归属；每次检索解析当前项目文献，显式选择必须属于项目。项目为空或消失时绝不退回全库。新会话创建时校验项目与文献，运行时再次校验。
- 内部项目支持创建、查看及添加/移除文献。侧栏按项目展示应用会话；新建页提供项目选择及文献标签。全库对话保留为明确的无项目选项。
- 项目组织不改变每个会话的独立 CLI 执行目录、原生 ID 续接和现有历史。项目共享文件推迟。
- 设置以 Node ServerSettingsService 为唯一默认值来源，服务端创建会话也应用默认值。默认值只影响新会话；切换工具清空不兼容模型。恢复 AI 工具状态和模型选择；现有使用量 API 保持可用，本轮不增加用量面板。
- 新建/已有会话复用 Composer。草稿按新建范围或会话 ID 存入 sessionStorage，成功发送后清空，错误时可恢复；首条消息在新建页提交后切到会话页续接流；消息 ID 保持幂等，响应丢失时按 ID 查询是否已接收。输入框处理组合输入、自动高度与停止。
- 卡片和详情只使用 LibraryPaper 与新资源接口；概览展示已有元数据/摘要，PDF 和全文沿用位置及引用定位。网格按行虚拟化，避免一次挂载全部文献。
- 恢复 Skills 浏览 API 的显式挂载，复用原 SCHOLARAIO_SKILLS_DIR 配置（默认 ~/scholaraio/skills；当前精简 Python 包未包含技能文档），不恢复通用项目扫描。

## Risks / Trade-offs

- 项目文献变更影响后续检索 → 已发送消息引用保持不变，显式选择失效时明确报错。
- 旧索引或符号链接越界 → 验证目录/索引实际路径；返回明确错误而非空列表。
- 首条消息重复发送 → 稳定消息 ID、服务端幂等和浏览器刷新测试。
- 底部面板占满视口 → 输入和审批区域限高可滚动，消息区保留独立滚动。

## Migration Plan

新增字段兼容现有 JSON；不重跑生产迁移。使用临时数据测试旧工作区和历史会话。回滚代码可继续读取已有字段和工作区索引；上线前保留现有备份。

## Open Questions

本轮无阻塞问题。项目重命名、共享文件及已删除的高级功能后续单独设计。

## 2026-09-21 补充：严格控制重构边界

用户明确：重构目标仅为统一 AI 消息格式和第三方消息渲染，其他页面、组件及交互应保持原样。此前“近似恢复”与不恢复高级 composer 的决定不能作为永久删减功能的授权。以 63fd364 的实际路由和组件为证据逐项恢复；优先直接复用组件，仅在数据接口处适配 app-owned sessions 与受管理文献库。原 `/library` 路由使用 SearchPage，而非未挂载的 LibraryPage 分析仪表盘；默认恢复 SearchPage，已有分析暂保留在显式 `view=analysis` 地址。语义、综合、作者检索接回原 ScholarAIO 服务，尊重已有配置与索引，缺少依赖时明确反馈。不会重新引入旧消息 HTML 增强和自定义工具消息渲染树。
